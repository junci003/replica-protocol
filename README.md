# 复刻协议 Replica Protocol

> 复刻不是抄界面，是把别人藏在界面里的判断，编码成自己的约束。

一套用于**复刻应用、工具、小程序**的方法论与可执行能力。目标不是做出"像它的东西"，而是做出**自己站得住的产品**。

---

## 为什么需要这个

复刻失败的项目，九成死在同一个地方：**把界面当成了要复刻的东西。**

于是预算全花在视觉上，做完发现"看起来像，但用起来不对"，也说不清差在哪。真正的原因在最底下那层——那个删掉产品就不成立的东西——从来没被拆开过。

这套协议的第一句话是：**你的承重墙是什么。**

| 目录 | 形态 | 用途 |

## 五步流程

```
判定 → 拆解 → 换皮 → 转化 → 自检
```

### 1 判定（3 分钟）

| 级别 | 骨架 | 皮 | 目的 | 成本 |
|---|---|---|---|---|
| **A 学结构** | 不动 | 不动 | 看懂它怎么做的 | 1–2 小时 |
| **B 做产品** | 不动 | 全换 | 变成自己的产品 | 半天 |
| **C 做能力** | 换 | 换 | 抽成可复用的 skill | 2–3 天 |

定错级是这类项目最大的浪费。**宁可往上猜一级，不要往下猜**——猜高了是加分项，猜低了是没做完。

### 2 拆解（出五张表，禁止散文）

信息架构、核心机制、状态流、数据结构、视觉 token。

承重墙三问：
1. 删掉这个模块，产品还成立吗？
2. 它产出的数据，别的模块是否都在读？
3. 用户真正付费/复用的是它，还是界面？

### 3 换皮（六件事，不是换色）

光源、底色、分层手段、圆角、主按钮、材质。

一条纪律：**主色在整屏只承担三件事**——可点击、当前选中、金额。

验收：遮住 logo，认不出原版，但功能一模一样。

### 4 转化（可选）

判断层（专家包，管"要不要"）/ 执行层（skill，管"多少"）/ 呈现层（视觉规范）。

剥离三判据全中才剥。**只有一版样本的东西不要抽象。**

### 5 自检（四维打分）

一致性、可执行性、约束完整性、边界清晰度。各 0–5 分，低于 3 分不交付。

3 分和 5 分的区别不在质量，在**可否被他人验证**。
"我觉得没问题"是 3 分；"图里 7 种花，清单 7 行，逐项对上了"才是 5 分。

## 安装

### 技能

```bash
# 复制到用户级 skills 目录
cp -r replica-protocol ~/.workbuddy/skills/
```

不用注册，重启后生效。

### 专家包

1. 把 `replica-engineer` 复制到 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/`
2. 运行注册脚本：

```bash
python "<WorkBuddy>/resources/app.asar.unpacked/resources/plugins/workbuddy-builtin/skills/expert-manager/scripts/register_expert.py" "<专家包绝对路径>"
```

3. 重新打开专家中心或重启客户端

**跳过注册，文件夹放对了也不会出现。**

## 边界

- **做重做，不做拷贝。** 界面布局与交互模式通常不受著作权保护（思想与表达二分），但图标、插画、文案、代码、商标受保护。本协议不复制对方任何素材文件，不沿用品牌标识。像素级克隆 + 同一市场 + 相似品牌，不在范围内。
- **复刻结构，不复刻内容。** 内容型产品（课程、资料库、资讯）的界面能复刻，内容不能。
- **看不到的不猜。** 只有截图时，交互细节、后台逻辑、后端约束都标注为未知，不基于猜测给方案。
